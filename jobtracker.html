Job Tracker

Job Application Tracker — Sync from Gmail/Outlook, Dashboard & Filters · Author: Wasim Ahmad · github.com/wasimahmadpk/JobTracker

Track applications in one place → Sync from email → See stats and status at a glance.

1. Project Overview

Job Tracker is a cross-platform app that helps users track job applications in one place. It syncs with Gmail and Outlook, automatically classifies job-related emails (applied, response, rejection, interview), and shows a dashboard with counts, filters, and search.

How it works

  • User signs in with Google or Microsoft (OAuth)
  • Backend fetches Sent and Inbox emails for a configurable lookback (1–12 months)
  • Each email is parsed with keyword and regex rules (no LLM): status and position/company are extracted
  • Applications are created or updated by email thread; duplicates are merged by company
  • User sees a home screen, dashboard (stats + pie chart), and a filterable list; can add applications manually and open "Position @ Company" detail views
StatusMeaning
AppliedYou sent an application; no reply yet
ResponseCompany acknowledged (e.g. We received your application)
RejectionNot moving forward

3. Architecture

The system separates the Flutter client, the FastAPI backend, and email providers. The backend is the single source of truth; the app never talks to Gmail/Outlook directly.

  • User (Browser / Android) → Flutter App (Vercel web / APK) → FastAPI Backend (Render)
  • Backend: /api/auth/* (Google/Microsoft OAuth, JWT), /api/me, /api/dashboard, /api/applications, /api/sync
  • Gmail API / Microsoft Graph (OAuth tokens per user) → email_parser.py → SQLite or PostgreSQL

Data flow (sync): User taps Sync (or changes lookback in Settings) → App calls POST /api/sync → Backend refreshes token, fetches Sent and Inbox for lookback window → Each message is parsed; sent emails create applied applications, inbox emails create or update by thread_id and status → Deduplication merges applications with the same company → App reloads dashboard and list.

4. Email Parsing (Keyword & Regex)

Classification is deterministic (no LLM): keyword lists and regex patterns detect status and extract position/company.

Response (acknowledgment): e.g. "thank you for applying", "we have received your application", "application is under review".

Rejection: e.g. "unfortunately", "not moving forward", "we have decided to move forward with other candidates".

Interview: Only when there is a clear invitation to schedule (e.g. "schedule a call", "invite you to an interview", "availability for a call", "calendly"). Generic "next steps" stay as Response.

Position & company extraction: Sent emails: patterns like "Application for <Position> at <Company>" or "<Position> - <Company>"; plus job-title keywords (scientist, engineer, developer, lead, manager). Inbox: e.g. "Thanks for applying to <Company>" → company extracted. Display format: Position @ Company.

5. Gmail & Outlook Sync

Gmail: OAuth scope includes Gmail read; backend stores refresh token per user. Sync fetches messages with in:sent newer_than:Nd and in:inbox newer_than:Nd (N = user's email_sync_days). Pagination up to a message cap; each message is fetched, parsed, and upserted by (user_id, email_thread_id). After sync, applications with the same company are merged.

Outlook: Microsoft OAuth; backend uses Microsoft Graph to read mail from Sent and Inbox for the same lookback window. Same upsert and deduplication logic as Gmail.

6. REST API (FastAPI)

All routes are under /api and require a valid JWT (except auth and health).

MethodPathDescription
GET/api/meCurrent user (email, settings)

GET/api/dashboardCounts: total, pending, responses, rejections, interviews
GET/api/applicationsList applications; query: status, search
POST/api/applicationsCreate application (manual)
GET/api/applications/:idGet one application

POST/api/auth/refreshRefresh JWT

7. Flutter App (Web, Android)

Screens: Splash (checks auth) → Login (Google, Microsoft, Demo) → Home ("Manage your job applications in one place"; quick actions: Dashboard, Applications, Settings) → Dashboard (stat cards, response rate bar, pie chart; cards open filtered list) → Applications (list with status chips and search; each row: "Position @ Company", date, status badge) → Application detail (full details, edit status/notes) → Add application (manual entry) → Settings (email lookback, account, sign out, About with version, developer, bugs: wasimahmad.qc@gmail.com).

Theme: Central AppColors in main.dart (e.g. navy primary); optional themes in docs/THEME-OPTIONS.md. Splash/login use gradient from primary/primaryLight.

8. Authentication (Google & Microsoft OAuth, JWT)

Google: Web: redirect to backend /api/auth/google/redirect; callback returns JWT. Mobile: in-app web view; redirect to jobtracker://auth/callback?token=JWT; app stores token and goes to Home. Backend stores refresh_token for Gmail (sync only).

Microsoft: App opens backend URL for Microsoft OAuth; after login, redirect with token; Outlook sync uses the same token.

JWT: Issued after successful Google/Microsoft login (or demo). Short-lived; client uses POST /api/auth/refresh. All API requests use Authorization: Bearer <token>.

9. CI/CD & Deployment

GitHub Actions: Build Android APK (Flutter, API_BASE_URL from secrets; upload APK as artifact). Deploy web to Vercel (Flutter web build, token and project IDs in secrets).

Hosting: Backend: Render (or Cloud Run, Railway). Web: Vercel. Mobile: user downloads APK from Actions artifact. Render free tier: service sleeps after inactivity (cold start on first request).

10. How to Run

Backend (local):

cd backend
python -m venv venv
source venv/bin/activate   # or venv\Scripts\activate on Windows
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000

API: http://localhost:8000 · Docs: http://localhost:8000/docs

Flutter app (web): cd app && flutter pub get && flutter run -d chrome. With remote backend: --dart-define=API_BASE_URL=https://your-backend.onrender.com

Flutter app (Android): flutter build apk --debug --dart-define=API_BASE_URL=.... Output: app/build/app/outputs/flutter-apk/app-debug.apk

Tests: cd backend && pytest
