DiaRisk

Diabetes risk scoring with production MLOps · Author: Wasim Ahmad · github.com/wasimahmadpk/diarisk

Eight clinical measurements in, a calibrated-style probability and risk band out — served as a public API on AWS Lambda with an ops UI, CloudWatch metrics, and live drift checks.

Interactive API docs → GitHub →

1. Overview

DiaRisk is a decision-support model trained on the Pima Indians Diabetes cohort (768 samples). It is not a medical diagnosis and the training population is women of Pima heritage in that study, not a general clinic.

Pipeline

  • Same 80/20 stratified split (seed 42) for logistic regression baseline and LightGBM
  • Zeros in glucose, blood pressure, skin thickness, insulin, and BMI treated as missing, then median-imputed
  • LightGBM test ROC-AUC ≈ 0.82; risk bands low / moderate / high from predicted probability
  • Joblib model in a FastAPI container (Mangum) on Lambda behind API Gateway; static UI on Vercel

4. Drift (honest scope)

Live data drift is not a statistical hypothesis test. Each /predict updates an in-process running mean. Then:

z = (live mean − train mean) / train std

|z| ≥ 3 flags a feature. Score drift uses the same idea on predicted probabilities versus the test-set score mix. True performance drop (AUC/F1) still needs labeled outcomes. Running means reset on Lambda cold start — no feature store or DynamoDB.

5. Delivery notes

  • Lambda image is linux/amd64 (GitHub ubuntu-latest / local --platform linux/amd64 on Apple Silicon)
  • Function URL returned 403 on this account; public HTTPS is API Gateway HTTP API
  • CORS preflight: explicit OPTIONS 204 so the browser UI can POST
  • Vercel hosts only static web/ — it must not pip-install the Python API
